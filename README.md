# マクドナルド注文BOT

Discord のパネルから注文コード (HEX) を投げると、登録済みのマクドナルド
アカウントで決済し、受け取り番号を DM で返す BOT です。
利用者は Kyash の送金リンクで残高をチャージし、その残高から支払います。
定価に対する負担率を設定でき、差額はオーナーの負担になります。

> 教育・研究目的の非公式実装です。自己責任でご利用ください。

---

## セットアップ

### 1. 依存の導入

```bash
pip install -r requirements.txt
```

### 2. main.py に書くのは2つだけ

`main.py` の冒頭を書き換えます。**直書きするのはこの2つだけ**で、
それ以外の設定はすべて Discord 上のコマンドで行います。

```python
DISCORD_TOKEN = "..."          # Discord の BOT トークン

OWNER_IDS = {
    123456789012345678,        # オーナーの Discord ユーザーID
}
```

### 3. Discord Developer Portal の設定

Bot ページで次の2つを有効にしてください。無効のままだと起動時にエラーになります。

* **MESSAGE CONTENT INTENT** … DM で感想を受け取るために必要
* **SERVER MEMBERS INTENT** … 紹介の不正判定で参加日時を見るために必要

### 4. 起動して、コマンドで設定

```bash
python main.py
```

起動したら Discord 側で設定します（すべてオーナー限定）。

```
/config setup        未設定の項目と手順を一覧表示
/config guild        このサーバーをコマンドの同期先にする
/config channel      パネル・実績・承認・各種ログのチャンネルを指定
/config role         注文できるロールを指定
/mcd login           マクドナルドにログイン（メール + パスワード + 確認コード）
/kyash login         Kyash にログイン（メール + パスワード + SMS の6桁）
/panel               利用者パネルを設置
/adminpanel          管理パネルを設置（任意）
```

**利用者はスラッシュコマンドを一切使いません。** すべてパネルのボタンで完結します。
サーバー設定で利用者のスラッシュコマンドを無効にしていても動作します。

`/config setup` が「設定は完了しています」になれば運用可能です。

トークンを直接入れる場合は `/mcd token` と `/kyash token` があります。
いずれも入力は Modal で受けるので、コマンド履歴にトークンは残りません。

アカウントは**どちらも複数登録できます**。マクドナルド側は LRU で選ばれ、
連続失敗すると自動で停止します。

### 5. あとから変える設定

```
/config show              現在の設定を一覧（* が既定値から変更済み）
/config set               負担率・上限・チャージ額・不正検知のしきい値など
/config rate-role         ロールごとの負担率
/config rate-user         利用者ごとの負担率
/config campaign-add      時間帯限定の負担率
/config terms             規約の版と本文（版を変えると全員に再同意を求める）
/config reset             項目を既定値に戻す
```

値は SQLite に保存されるので、再起動しても残ります。

## 利用者の流れ

利用者の操作はすべてパネルのボタンです。スラッシュコマンドは使いません。

```
利用者パネル（/panel で設置）
 ├ 注文する      規約同意 → 注文コードを貼る → 内容確認 → 決済
 │                └ 定価が上限超過ならオーナー承認へ
 ├ チャージ      Kyash の送金リンクを貼る → 残高に反映
 ├ 残高・履歴    残高、台帳の動き、注文履歴
 ├ 紹介コード    自分のコードの確認、他人のコードの入力
 ├ 自分の負担率  いま適用されている割引率と支払額の例
 └ ランキング    今月の利用ランキング

注文が確定すると
 ├ 利用者の DM へ 受け取り番号カード + 明細
 ├ 実績チャンネルへ 1段階目（メンションと受取方法のみ）
 └ 呼び出し番号が出たら DM で通知

その後
 └ BOT へ DM で感想を送る（次回注文の条件）
    └ 本人が承諾 → オーナーが承認 → 実績チャンネルへ投稿
       └ 画像を添えていれば残高ボーナス
```

**2段階目が承認されるまで次の注文はできません。** オーナーは
`/mcd unlock @user` または管理パネルの「ロック解除」で個別に解除できます。

## 管理者の操作

スラッシュコマンドと、`/adminpanel` で設置する管理パネルの
どちらからでも操作できます。

```
管理パネル（オーナーのみ操作可。他の人が押しても弾かれる）
 ├ ダッシュボード / 承認待ち / 不正フラグ
 ├ アカウント状態 / 設定一覧 / 台帳監査 / 監査ログ
 ├ 残高を調整 / ロック解除 / 利用停止 / 停止を解除 / 利用者の状況
 └ 注文の受付を切り替え / バックアップを取る / 起動時の点検をやり直す
```

アカウントの登録（`/mcd login` `/kyash login`）と設定の変更（`/config` 系）は
入力項目が多いためスラッシュコマンドのみです。

### 代理での実績投稿

利用者が DM 以外の経路で感想を送ってきた場合、`/proxyreport` で代理投稿できます。

```
/proxyreport user:<利用者> content:<感想> [order_id] [image1..3]
```

実績チャンネルへの投稿は通常のものと同じ形で出ます。代理であることは
**管理ログチャンネルと監査ログにのみ**記録されます。画像の使い回しチェックと
画像ボーナスは通常の投稿と同じ基準で動き、投稿すると注文ロックも解除されます。

## 料率の決め方

率は一貫して「**利用者が定価の何%を払うか**」です。60 なら定価 590 円が 354 円。
小さいほど利用者が得をします。

優先順位は次のとおりで、個別設定がなければ**利用者に一番有利な率**が採用されます。

```
ユーザー個別設定 (USER_RATES)
   └ なければ min(ロール別 ROLE_RATES, 適用中の CAMPAIGNS, 既定 DEFAULT_USER_RATE)
```

`/myrate` で自分に適用される率を確認できます。

## 設計上の要点

### 残高は台帳の合計が正

`users.balance` は写像で、真実は `ledger` テーブルにあります。
`/mcd audit` で両者を突き合わせ、ズレがあれば検出できます。
決済に失敗したら `refund` 行を足して戻すので、履歴が消えません。

### アカウントごとにロックを分ける

マクドナルドの `refresh_token` は API を叩くたびに新品へ差し替わります。
同じアカウントを並行で叩くと片方が即失効するため、**アカウントごとに
`asyncio.Lock` を持って直列化**し、更新のたびに DB へ書き戻しています。
Kyash は別系統のロックなので、チャージが注文を塞ぎません。

### 課金の前後で再試行の可否を分ける

| 失敗した場所 | 扱い |
|---|---|
| 認証 | 他のアカウントへ乗り換えて再試行 |
| StoreOrder | 課金前なので返金し、注文コードを解放して再試行可 |
| AuthoriseOrder（明確なエラー） | 返金するが、注文コードは解放しない |
| AuthoriseOrder（応答なし） | **自動リトライも自動返金もしない**。`unknown` として記録し、オーナーに通知 |

応答が返ってこなかった場合は課金されたか判断できないため、黙って再送せず
安全な側に倒しています。オーナーが確認して `/mcd adjust` で調整してください。

### 二重決済の防止

注文コードの SHA-256 を `orders.hex_sha256` の UNIQUE 制約で押さえます。
**残高を引く前**に枠を確保するので、連打やリトライで二重に課金されません。
Kyash の送金リンクも `link_uuid` を同じ方式で押さえています。

### 決済成否不明の自動照合

`AuthoriseOrder` の応答が切れると課金の有無が分かりません。この注文は
`unknown` として記録し、10分おきに `GetPaidOrder` で照会します。

| 照会の結果 | 動き |
|---|---|
| 課金されていた | `paid` に戻し、感想待ちにする。残高はそのまま |
| 登録されていない | `failed` にして**自動で返金**し、注文コードを解放する |
| 判断できない | 触らず次回に回す |

結果は本人と各ログチャンネルに通知されます。手作業での突き合わせは不要です。

### サーキットブレーカー

決済が続けて失敗すると自動でメンテナンスモードに入り、パネルが停止表示に
変わります。設定した時間が経つと接続を確認し、回復していれば自動で再開します。
手動での切り替えは管理パネルの「注文の受付を切り替え」から行えます。

### バックアップ

毎日決まった時刻に SQLite の backup API でコピーを取り、設定した世代数だけ
保持します。`/config restore` で復元でき、**復元の直前には現在の状態も
自動で保存**されるので誤復元からも戻せます。

### ログ

* `logs/bot.jsonl` に構造化ログ（日次ローテーション）
* 出力の直前でトークン・PASETO・JWT・カード番号・パスワードを自動マスク
* Discord 側は注文 / 入出金 / エラー / 管理操作でチャンネルを分離
* `/mcd logs` で監査ログを参照

### 不正検知

| 対象 | 内容 |
|---|---|
| 紹介 | 自己紹介・循環・重複・紹介元の実績なし・上限超過を拒否。アカウント年齢、参加からの経過時間、同一 Kyash からのチャージを減点。報酬は初注文の実績承認後に付与し、直前に再判定 |
| 多重アカウント | 同じ Kyash アカウントが複数の Discord ユーザーにチャージしていないか |
| 画像の使い回し | 差分ハッシュで過去の投稿と照合し、一致したら拒否 |
| 注文 | 短時間の連続注文、高額注文 |

スコアが閾値を超えるとオーナー承認へ回り、`/mcd flags` で一覧できます。

## 運用上の注意

* **Kyash のアクセストークンは約30日で失効します。** 期限が近づくと
  ヘルスチェックがオーナーに警告するので、`/kyash login` で再登録してください。
* チャージした残高は返金しない設計です。規約同意 (`TERMS_VERSION`) で
  明示し、同意日時を記録しています。例外対応が必要な場合は
  `/mcd adjust` で個別に調整してください。
* 定価と利用者負担の差額はオーナーの持ち出しです。`/dashboard` で
  当日と当月の持ち出し額を確認できます。
* 番号カードの日本語表示にはフォントが必要です。見つからない場合は
  起動時に警告が出るので、`main.py` の `FONT_PATH` を設定してください。
