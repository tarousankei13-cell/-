# マクドナルド Discord 注文BOT

利用者は Kyash でチャージし、Discord のパネルから注文します。
管理者が設定した**負担率**の分だけ支払いが割り引かれ、注文後は注文番号を
差し替えたレシート画像が DM に届きます。

---

## 1. 動かすまで

### 1-1. 必要なもの

- Python 3.11 以上
- Discord BOT のトークン
- マクドナルドのアカウント（決済カード登録済み）
- Kyash のアカウント

### 1-2. インストール

```bash
pip install -r requirements.txt
```

必要なパッケージは8つだけです（Discord・DB・通信・暗号化・画像生成）。
PostgreSQL を使う場合は `requirements.txt` の `asyncpg` のコメントを外してください。

### 1-3. 設定

**必須なのは2つだけ**です。`main.py` 冒頭の「設定ブロック」に書きます。

```python
DISCORD_TOKEN = "ここにトークンを貼る"      # ← 必須
OWNER_IDS = [あなたのDiscordユーザーID]    # ← 必須
```

> #### ★ 貼り付けるときの注意
> ```python
> DISCORD_TOKEN = "ここに貼る"
> #               ↑        ↑  この2つのダブルクォートは消さない
> ```
> 片方でも消すと `SyntaxError: unterminated string literal` になります。

残りは**そのままで構いません**。

| 項目 | 既定 | 説明 |
|---|---|---|
| `ADMIN_ROLE_IDS` | `[]` | 管理者パネルを使えるロール（任意） |
| `GUILD_ID` | `None` | サーバーIDを入れるとコマンドが即時反映 |
| `ENCRYPTION_KEY` | `""` | **空でOK。初回起動時に自動生成します** |
| `DATABASE_URL` | SQLite | そのままで動きます |

#### 環境変数でも設定できます

ホスティングサービスの環境変数に入れても構いません。
`main.py` が空欄なら、そちらを読みます。

| 環境変数 | 対応する設定 |
|---|---|
| `DISCORD_TOKEN`（`TOKEN` / `BOT_TOKEN` も可） | BOTトークン |
| `OWNER_IDS` | オーナーID（カンマ区切り 例 `123,456`） |
| `ADMIN_ROLE_IDS` / `GUILD_ID` / `DATABASE_URL` | 同名の設定 |

> ### ⚠️ `main.py` に直接書いた場合
> トークンが平文で入ります。**公開リポジトリへ push しないでください。**
> GitHub に上げる場合は `.gitignore` の `# main.py` のコメントを外してください。

#### 暗号化キーについて（触らなくて大丈夫です）

登録したアカウント情報をDBの中で暗号化するための鍵です。
初回起動時に自動生成され、`data/encryption_key.txt` に保存されます。

これにより、**Discordへ送るバックアップだけが漏れても、
マクドナルド・Kyashのアカウント情報は読み取られません。**

- この鍵を失っても、**残高と注文履歴は無事**です（暗号化していません）
- 失った場合はアカウントを登録し直すだけで元どおり使えます

### 1-4. Discord 側の設定

Developer Portal → あなたのアプリで:

1. **Bot** タブ → トークンを取得
2. **OAuth2 → URL Generator** → スコープ `bot` と `applications.commands`
3. 権限: メッセージを送信 / 埋め込みリンク / ファイルを添付 / メッセージ履歴を読む
4. 生成された URL でサーバーへ招待

> 特権インテントの申請は**不要**です（感想ゲート機能を ON にする場合のみ必要）。

### 1-5. 起動

```bash
python main.py
```

`ログインしました: ...` と表示されれば成功です。

## 2. 初回セットアップ（この順番で）

BOT を招待したら、管理者が次の順に実行します。

```
1.  /config subsidy global 40          負担率を決める（40なら利用者は60%払う）
2.  /config channel admin   #bot-管理   管理者への通知先
3.  /config channel achievement #実績   実績の投稿先
4.  /mcd add                           マクドナルドアカウントを登録
5.  /kyash add                         Kyashアカウントを登録
6.  /panel charge #チャージ             チャージパネルを設置
7.  /panel order  #注文                注文パネルを設置
8.  /panel admin  #bot-管理             管理パネルを設置
```

### アカウント登録の流れ

`/mcd add` と `/kyash add` は、メールとパスワードを入力したあと
**SMS やメールで届く6桁の認証コード**が必要です。手元に端末を用意してください。

- Kyash は一度登録すれば、次回から認証コードなしで再ログインできます
- マクドナルドは登録後に**決済カードを選ぶ画面**が出ます

## 3. 利用者の使い方

すべてパネルのボタンから操作します。

**チャージ** → Kyash アプリで送金リンクを作る → パネルの `🔗 チャージする` に貼る

**注文** → パネルの `🍔 注文する` →
- `📋 注文コード(HEX)を貼る` … 他で作ったコードで注文
- `🍔 メニューから選ぶ` … お店を探して商品を組み立てる

メニューから選ぶときの流れ:

```
カテゴリ → 商品一覧 → 商品の詳細 → カート → お受け取り方法 → 確認
                         │
                         ├ 1個／2個／3個 追加
                         ├ カスタマイズ（ピクルス抜き・氷抜きなど）
                         └ セットは「中身を選ぶ」
```

商品の詳細では、**写真・説明・価格・提供時間・ご注意**が出ます。
公式のアレルギー・栄養情報ページへのボタンも付きます。

> お受け取り方法（店内でお召し上がり／お持ち帰り）は**最後に1回だけ**聞きます。
> 中身が決まる前に選んでも迷うだけなので、実物のアプリと同じ順番にしてあります。

**お店の探し方** → `🔍 店名でさがす` に**店名の一部**を入力
```
南砂     → 南砂町店
AKIBA    → ビックカメラＡＫＩＢＡ店
江東区   → 住所でも探せます
13934    → 店舗IDでも指定できます
```

> 店名は**漢字**で入力してください（`まえばし` ではなく `前橋`）。
> 全国3,036店舗・全47都道府県が登録されています。
ひらがな・カタカナ・全角半角のどれでも当たります。

**注文コードだけ作る** → `🧾 注文コードを作る`（決済はしません）

### 残高の増減は、その場に出ます

チャージしたとき・注文したときは、**操作したチャンネル**に
「誰がいくら増えた／減った」が**誰にでも見えるパネル**で出ます。
共有の財布として、お互いの利用が見えているほうが分かりやすいためです。

```
👛 チャージ
　ご利用者  たろう　　増減  +¥3,000　　内容  Kyash でチャージ
```

出す内容は管理者が選べます。

| | 既定 | 備考 |
|---|---|---|
| ご利用者名 | 表示 | `name` を切ると匿名コード（`U-7F3A`）になります |
| 増減額 | 表示 | |
| **残高** | **非表示** | いくら持っているかは見えません |
| 内容 | 表示 | チャージ／注文した店舗名 |
| 利用回数 | 非表示 | |

```
/config balance_panel enabled:True balance:False     表示項目を選ぶ
/config balance_panel enabled:False                  パネルを出さない
/config channel balance #残高ログ                     1か所にまとめて出す
```

> DM での操作では出しません（「誰にでも見える」が成り立たないため）。

## 3.5 注文番号ページ（任意）

店頭で注文番号を見せるためだけの小さなサイトを、BOT が自分で配信できます。
追加のインストールは要りません。

```
/config web enable base_url:https://example.com/order port:8080
```

前段の nginx などから `127.0.0.1:8080` へ回してください。

### ホスティングサービスに置く場合

Render / Railway / puratya などに置くときは、**設定は要りません**。
環境変数 `PORT` が渡されていれば、それを見て自動で立ち上がります。

| 環境変数 | 役割 |
|---|---|
| `PORT` | 待ち受けるポート（サービスが決めます） |
| `HOST` | 待ち受けるアドレス（未指定なら `0.0.0.0`） |
| `WEB_BASE_URL` | 控えに出すリンクの元。例 `https://xxxx.example.com/order` |

### BOT と別の場所に置く場合

`receipt_site/` を別のサーバーに置いてください（専用のZIPがあります）。
データベースを共有せず、**BOT が注文のたびに送る**方式です。

```
BOT（別の場所）                 ページ（receipt_site）
  注文成立 → 注文番号を送信  →   受け取って保存 → 表示
          合い言葉（PUSH_SECRET）を両方に入れるだけ
```

1. ページ側: 環境変数 `PUSH_SECRET` に長めの合い言葉を入れて起動
2. BOT 側: `/config web remote api_url:https://…/api/receipts secret:同じ合い言葉`
3. `/config web test` でつながるか確認

ページ側には**残高も認証情報も置かれません**。再起動で消える環境でも、
失われるのはその時点の注文番号ページだけです。

> 合い言葉はそのまま流れません。BOT は指紋（SHA-256）を送ります。
> 日本語の合い言葉も使えます。

```nginx
location /order/ {
    proxy_pass http://127.0.0.1:8080/order/;
}
```

- URLには**推測できない合い言葉**が入ります。注文番号（4桁）をURLに
  していないので、順に試して他人の注文を覗くことはできません
- 出すのは**注文番号・店舗名・受取方法・時刻**だけです。
  いくら払ったか、誰が頼んだかは出しません
- 既定で**12時間**経つと開けなくなります（`/config web expire`）
- 検索避け（noindex）とキャッシュ無効を付けています

> このページが無くても注文番号は DM の控えに入っています。
> サイトが落ちても注文には影響しません。

## 3.6 招待キャンペーン（任意）

お友だちを招待した人に残高を配れます。**実際にお金が出ていく**ので、
既定では停止しています。

```
/config campaign start reward:300 budget:10000 max_per_user:5
/panel invite #招待
```

| 歯止め | 内容 |
|---|---|
| 全体の予算 | 超える分は配らない（`budget`） |
| 1人あたり | 1人が特典をもらえる招待の上限（`max_per_user`） |
| 条件 | 既定は**お友だちのはじめての注文**。参加しただけでは配りません |
| 二重払い | 1人は一度しか招待されません（DBの形で保証） |
| 自作自演 | 自分のコードは使えません |

招待の紐づけは2通り使えます。

1. **招待コードを本人が入力**（既定・権限不要）
2. **Discordの招待を自動追跡**　`main.py` の `INVITE_AUTO_TRACK = True`
   ⚠️ Developer Portal → Bot → **SERVER MEMBERS INTENT** を有効にしてください。
   有効にせず True にすると BOT が起動しません。
   同時に2人入室したときは取り違えを避けて紐づけを見送り、1 に任せます。

## 4.5 注文方式と同期の設定

### 注文方式を絞る

```
/config order_mode both   両方（既定）
/config order_mode hex    注文コード(HEX)のみ
/config order_mode menu   メニューから選ぶ方式のみ
```

片方に絞ると、利用者は選択画面を挟まず直接その方式に進みます。
`menu` にすると「注文コードを作る」ボタンはパネルから消えます。

> 変更後は `/panel refresh` で、設置済みパネルに反映してください。

### 商品・時間帯・店舗の同期

商品や価格、朝マック・夜マックの提供時間、店舗そのものはマクドナルド側で
随時変わります。本BOTは**15分ごと**にこれを取り込みます。

```
/config menu interval 15         商品・提供時間帯（5〜1440分）
/config menu store_refresh 30    店舗情報・営業時間（5〜1440分）
/config store interval 15        店舗一覧の巡回更新（5〜1440分）
```

**店舗一覧の同期**は2段構えです。

| 間隔 | 内容 |
|---|---|
| 15分 | 確認が古い店舗から400件ずつ取り直す（全3,036店舗を約2時間で一周） |
| 60分 | 公式の店舗検索サイトと照合し、開店・閉店を調べる |

新店舗の開店・閉店・店名変更・モバイルオーダー対応の切り替えを検出すると、
管理者チャンネルに通知します。ETag に対応しているため、変化が無ければ
**通信量は0バイト**で済み、短い間隔でも負荷はかかりません。

> 💡 **短くしても負荷はほとんど増えません。**
> 内容に変更が無ければサーバーが「変わっていません」と返すだけで、
> データの受信が発生しないためです（ETag / 304）。
>
> 日付が変わったタイミングでは、提供時間帯の定義が切り替わるため
> 必ず取り直します。

## 5. 困ったときは

### コマンドが2つずつ表示される

同じコマンドがグローバルとサーバーの両方に登録されている状態です。
本BOTは起動時に自動で片方を消しますが、直らない場合は:

1. `main.py` の `GUILD_ID` を**どちらかに決める**（サーバーIDを入れる or `None`）
2. `/sync` を実行
3. Discord アプリを再起動

### コマンドが表示されない

- `GUILD_ID = None`（グローバル）の場合、反映に**最大1時間**かかります
- すぐ反映させたいときは `GUILD_ID` にサーバーIDを入れてください

### 「要確認」の注文が出た

課金が成立したかどうか分からない状態です。**BOTは勝手に返金しません。**

1. マクドナルドのアプリや店舗で、実際に注文が通っているか確認
2. 管理パネルの `⚠️ 要確認` から「成立」か「返金」を選ぶ

### 残高がおかしい

`/stats ledger` で元帳の整合性を確認できます。
「不整合あり」と出た場合は、その内容を添えて開発者に連絡してください。

### 店名で検索できない

`/store info` で状態を確認できます。

- **「店舗一覧が読み込まれていません」** と出る場合
  `assets/stores.json` が無い状態です。`/store reindex` で作成できます（3〜5分）。
  一覧が無くても、店舗IDを直接入力すれば注文できます。
- 一覧はあるが特定の店が出ない場合
  新しくできた店舗かもしれません。**店舗IDで指定**すれば注文できます

### 注文方法を1つに絞りたい

```
/config order_mode menu     メニューから選ぶ方式のみ
/config order_mode hex      注文コード(HEX)のみ
/panel refresh              パネルに反映
```

---

### アカウントが `🔴` になった

連続して失敗したため自動で隔離されています。

```
/mcd health          状態を確認
/mcd enable <ID>     復帰させる
```

Kyash は**アクセストークンが1ヶ月で失効**します。
期限が近づくと管理者チャンネルへ通知が届くので `/kyash relogin <ID>` を実行してください。

## 6. バックアップ

SQLite を使っている場合、**毎日1回データベースを管理者チャンネルへ自動送信**します
（既定は午前4時）。`/admin backup` でいつでも手動取得もできます。

無料ホスティングでデータが消えても、このファイルがあれば**残高と注文履歴を復元**できます。
**管理者チャンネルは必ず設定してください。**

登録済みアカウントまで戻したい場合は、サーバー上の `data/encryption_key.txt` も
一緒に保管しておいてください（バックアップには含めていません）。

## 7. 開発者向け

### テスト

```bash
python tests/run_all.py
```

### 構成

```
main.py              起動・設定・コマンド同期
config.py / emoji.py 既定値・絵文字定数
db/                  モデル・接続
core/                元帳・排他制御・暗号化・負担率・注文Saga・設定
services/mcd/        protobuf・APIクライアント・メニュー・アカウント・店舗
services/kyash/      Kyash API・口座管理・チャージ
services/receipt.py  レシート画像生成
ui/                  パネル・埋め込み・操作フロー
cogs/                スラッシュコマンド・定期タスク
docs/                設計書（01〜09）
```

設計の詳細は `docs/README.md` を参照してください。
特に注文の状態遷移は `docs/04` §4、絶対に守るルールは `docs/06` §0 にあります。

### データベースを PostgreSQL に移す

`main.py` の `DATABASE_URL` を書き換えるだけです。

```python
DATABASE_URL = "postgresql+asyncpg://user:pass@host/dbname"
```

`pip install asyncpg` も必要です。
