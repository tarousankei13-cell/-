# 05. コマンド・UI 仕様書

> 絵文字は `emoji.py` の定数のみを使う（`docs/04` §9）。カスタム絵文字は使用しない。
> 全コマンドは `app_commands`（スラッシュ）で実装する。`hybrid_command` は使わない（`docs/04` §8）。

## 2. チャージフロー

### 2.1 チャージパネル（常設・指定チャンネル）

```
┌─────────────────────────────────────────────┐
│ 💴 残高チャージ                               │
│                                             │
│ Kyash の送金リンクで残高をチャージできます。    │
│                                             │
│ ▸ Kyash アプリで「送金リンク」を作成          │
│ ▸ 下のボタンからリンクを貼り付け              │
│ ▸ 受け取りが完了すると即座に残高へ反映されます  │
│                                             │
│ ℹ️ 1回のチャージは ¥100 〜 ¥50,000 です       │
│ ⚠️ 請求リンクは受け付けできません              │
│ ⚠️ チャージした残高の払い戻しはできません      │
└─────────────────────────────────────────────┘
   [ 🔗 チャージする ]   [ 👛 残高を確認 ]
```

- `View` は `timeout=None` の永続ビュー。`custom_id` を固定し、`setup_hook` で `add_view()` する
- 再起動後もボタンが生き続けるようにすること

### 2.2 チャージ Modal

```
タイトル: 💴 残高チャージ
 ┌ Kyash 送金リンク ───────────────────────┐
 │ https://kyash.me/payments/xxxxxxxx      │
 └─────────────────────────────────────────┘
   （リンクのIDだけでも入力できます）
```

### 2.3 処理と応答（すべて ephemeral）

| 状況 | 応答 |
|---|---|
| 処理中 | `⏳ リンクを確認しています…`（`defer(ephemeral=True)`） |
| 成功 | `✅ チャージ完了` / 受取額・反映後残高・送金者名 |
| 請求リンク | `❌ 請求リンクは受け取れません。送金リンクを作成してください` |
| 処理済み | `❌ このリンクは既に使用されています` |
| 金額範囲外 | `❌ チャージ額は ¥100 〜 ¥50,000 の範囲で指定してください` |
| 残高差分が不一致 | `⚠️ 確認中です。管理者が対応しますのでお待ちください`＋管理者へ通知 |
| Kyash口座なし/全停止 | `❌ ただいまチャージを受け付けできません` ＋管理者へ通知 |

処理手順は `docs/03` §3.1 を厳密に守ること（**受取成功 → 残高検証 → 記帳** の順序）。

## 3. 注文フロー

### 3.1 `/order` → hex 入力 Modal

```
タイトル: 🍔 注文する
 ┌ 注文コード（HEX） ──────────────────────┐
 │                                         │  ← 複数行・必須
 └─────────────────────────────────────────┘
```

### 3.2 プレビューパネル（ephemeral）

hex をデコードして内容を提示し、ここで**受取方法を選ばせる**（R-2）。
このパネルが開いた瞬間に**投機的先読み**を開始する（`docs/04` §5.3）。

```
┌─────────────────────────────────────────────┐
│ 🍔 注文内容の確認                             │
│                                             │
│ 🏪 店舗       代々木店 (10528)                │
│ 🧾 商品数     3 点                            │
│ 💴 定価       ¥590                           │
│                                             │
│ 👤 あなたの負担率   60%  （負担 40% 適用中）    │
│ 💴 お支払い額       ¥354                      │
│ 👛 チャージ残高     ¥630 → ¥276               │
│                                             │
│ 📍 受取方法を選んでから確定してください          │
└─────────────────────────────────────────────┘
  [ 📍 受取方法を選択 ▼ ]
  [ ✅ 注文を確定する ]  [ ❌ キャンセル ]
```

- **受取方法セレクト**: `テイクアウト` / `店内（カウンター受取）` / `店内（席まで）` / `デリバリー`
  ⚠️ `docs/01` §11 の V-1 が未確定の間は **テイクアウト以外を `disabled` にし、説明文に「準備中」**と表示
- 受取方法が未選択の間は「注文を確定する」を `disabled`
- 残高不足なら確定ボタンを `disabled` にし、`[ 🔗 チャージする ]` を出す
- パネルの `timeout` は 120 秒。失効時は「時間切れです。もう一度お試しください」に置換
- 確定ボタンの `custom_id` に **`idempotency_key`（UUID）** を埋め込む（`docs/04` §4.1-4）

### 3.3 進捗パネル（同一メッセージを編集し続ける）

無言の待ち時間を作らない。**これが「超高性能」の体感を最も左右する。**

```
⏳ 注文を処理しています…

✅ ① 残高を確保しました            ¥354
✅ ② 店舗を確認しました            代々木店
🔄 ③ マクドナルドへ送信しています…
⬜ ④ 注文番号を取得
```

各段階の完了時に `interaction.edit_original_response()` で更新する。

### 3.4 完了（ephemeral）

```
✅ 注文が完了しました
　 詳細と控えを DM にお送りしました。
```

DM が送れない場合（DM拒否設定）:

```
⚠️ 注文は完了しましたが DM を送信できませんでした
　 注文番号: 7161
　 DM の受信を許可してから、もう一度お試しください。
```

→ この場合も**注文自体は成立している**ため、注文番号を必ずその場に表示すること。

## 4. DM 完了パネル（R-10 / 添付画像1・2 相当）

> **E-4 の要望により、元パネルから文言を刷新する。** 項目は同等、表現を変更。

### 4.1 Embed 仕様

| 属性 | 値 |
|---|---|
| color | `0x2ECC71`（緑） |
| title | `✅ ご注文が確定しました` |
| description | `マクドナルドでの注文が成立しました。\n下のレシート画像は必ず保存しておいてください。` |
| thumbnail | BOT のアバター |
| image | 生成したレシート画像（`attachment://receipt.png`） |
| footer | `ご利用ありがとうございます` ＋ タイムスタンプ |

**フィールド**

| name | value | inline |
|---|---|---|
| `🧾 注文番号` | ``` `7161` ``` | true |
| `🏪 店舗` | `代々木店\n`` `10528` `` ` | true |
| `📍 受取方法` | `カウンター受け取り（店内）` | true |
| `💴 お支払い` | `**¥354**\n定価 ¥590 のうち 60%（負担 40% 適用）` | false |
| `👛 残りの残高` | `**¥276**` | true |
| `🍟 ご利用回数` | `通算 1 回目` | true |

初回注文時のみ、末尾に追記:
`🎉 はじめてのご注文ありがとうございます！`

### 4.2 感想ゲート（任意機能・既定 OFF）

`/config feedback on` のときだけ、以下のフィールドを追加する。
OFF のときはこのセクションを**完全に省略**する。

| name | value |
|---|---|
| `📝 ご感想のお願い` | `このメッセージへの返信でご感想をお送りください。\n次回のご注文時に必要となります。\n・テキストのみで構いません\n・お写真の添付は任意です` |

> ON にする場合のみ `Intents.message_content` を有効化し、Discord 開発者ポータルで
> Message Content Intent を申請すること。OFF のままなら**申請不要**。

### 4.3 レシート画像

- `assets/templates/receipt.png`（= 添付画像3）の**注文番号だけ**を実値へ差し替える（R-10 / E-2）
- 生成手順は `docs/04` §6
- `discord.File(buf, filename="receipt.png")` として Embed と同時に DM 送信

## 5. 実績パネル（R-11 / F-1・F-2）

**プライバシー重視。注文確定時に指定チャンネルへ1回だけ送信する。**
感想の追記やスレッド運用は行わない。

### 5.1 既定の表示内容

```
┌─────────────────────────────────────────────┐
│ ✅ 注文が成立しました                          │
│                                             │
│ 👤 利用者      U-7F3A                        │
│ 💴 定価        ¥590                          │
│ 📊 負担率      40%                           │
│ 💴 お支払い    ¥354                          │
│ 🍟 通算        本日 12 件目                   │
│                                             │
│ 2026-09-29 12:34                            │
└─────────────────────────────────────────────┘
```

- **ユーザー名・ID・メンションは出さない。** `users.anon_code`（例 `U-7F3A`）のみ
- **店舗名・注文番号・商品内容は既定で出さない**（居場所と注文内容が特定されうるため）
- `anon_code` は `discord_id` から導出した安定ハッシュの先頭4桁（利用者ごとに一意・不変）

### 5.2 表示項目のカスタマイズ

`/config achievement fields` で以下から選択できるようにする。

| 項目 | 既定 |
|---|---|
| `anon_code`（匿名コード） | ✅ ON |
| `list_price`（定価） | ✅ ON |
| `subsidy_rate`（負担率） | ✅ ON |
| `user_amount`（お支払い額） | ✅ ON |
| `daily_count`（本日の通算） | ✅ ON |
| `username`（ユーザー名） | ❌ OFF |
| `store_name`（店舗名） | ❌ OFF |
| `receipt_number`（注文番号） | ❌ OFF |
| `pickup_method`（受取方法） | ❌ OFF |

## 6. アカウント追加フロー（R-8 / C-2）

### 6.1 `/mcd add`

```
Modal「🔑 マクドナルドアカウントを追加」
 ┌ 表示名（任意） ─────────┐
 ┌ メールアドレス ─────────┐
 ┌ パスワード ────────────┐      ← ⚠️ ephemeral。入力値は即暗号化し破棄

   ↓ login(email, password) → jwtMfaToken

Modal「🔑 認証コードの入力」
 ┌ SMS/メールで届いた6桁 ───┐

   ↓ login_with_mfa(mfa_token, otp) → refresh_token

   ↓ get_cards() → カード一覧
Select「💳 決済に使うカードを選択」
   ↓ card_id を保存

   ↓ 端末フィンガープリントを生成して固定（docs/04 §5.1）
✅ 登録完了（ephemeral）
```

- `jwtMfaToken` の有効期間は短いため、**1つ目の Modal 送信から続けて2つ目を開く**
- OTP を3回間違えたら中断し、最初からやり直させる
- 登録直後にヘルスチェックを1回実行し、失敗したら `DEGRADED` で登録する

### 6.2 `/kyash add`

```
Modal「🔑 Kyashアカウントを追加」
 ┌ 表示名（任意） ─────────┐
 ┌ メールアドレス ─────────┐
 ┌ パスワード ────────────┐

   ↓ Kyash(email, password) → SMS送信

Modal「🔑 認証コードの入力」
 ┌ SMSで届いた6桁 ────────┐

   ↓ login(otp)
   ↓ access_token / client_uuid / installation_uuid を暗号化保存
   ↓ get_profile() → is_kyc / get_wallet() → 残高
✅ 登録完了（ephemeral）
```

⚠️ `client_uuid` と `installation_uuid` は**2つで1セット**。
これを保存しておけば以後の再ログインで OTP が不要になる（`docs/03` §2.1）。**必ず両方保存すること。**

## 7. エラーメッセージ規約

すべて ephemeral で返し、**利用者に次の行動を示す**。

| 状況 | メッセージ |
|---|---|
| 残高不足 | `❌ 残高が不足しています\n必要 ¥354 / 現在 ¥120` ＋ `[ 🔗 チャージする ]` |
| hex が不正 | `❌ 注文コードを読み取れませんでした\nコードをもう一度確認してください` |
| hex の金額が 0 | `❌ この注文コードには金額が含まれていません` |
| 受取方法が未選択 | `⚠️ 受取方法を選択してください` |
| 注文が進行中 | `⏳ 前回の注文をまだ処理しています。完了までお待ちください` |
| アカウント枯渇 | `❌ ただいま注文を受け付けできません。時間をおいてお試しください` ＋管理者へ通知 |
| メンテナンス中 | `🔧 ただいまメンテナンス中です` |
| 利用停止 | `🚫 ご利用が停止されています` |
| 課金済みだが不明な失敗 | `⚠️ 注文の確認に時間がかかっています\n管理者が確認していますので、そのままお待ちください` ＋管理者へ通知 |

> 最後のケースでは **絶対に「失敗しました」と表示しない。**
> 実際には課金・注文が成立している可能性があるため（`docs/04` §4.1-2）。

## 8. 管理者通知（管理者チャンネルへ）

| 事象 | 内容 |
|---|---|
| 🔴 アカウント隔離 | どのアカウントが、何回連続失敗で `QUARANTINED` になったか |
| 🟡 Kyashトークン期限接近 | 残り日数と対象アカウント、`/kyash relogin <ID>` への導線 |
| ⚠️ 元帳の不整合 | 破れた `tx_id` と差額 |
| ⚠️ MANUAL_REVIEW 発生 | 注文/チャージの詳細 ＋ `[ ✅ 完了として処理 ]` `[ 💴 返金する ]` ボタン |
| ⚠️ チャージの残高差分不一致 | リンクUUID・想定額・実差分 |
| 🔴 Kyash link_check の解析失敗 | HTML構造の変更が疑われる旨 |
